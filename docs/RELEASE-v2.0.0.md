> 对应提交：`2900fa0` ~ `103eaa9`（2026-11-27）
> 规范：`docs/SPEC-v2.md`（JR-SPEC-2.0）
> 版本串：`jrust 0.1.0 (spec 2.0)` —— 实现版本号暂未随规范 MAJOR 提升，以 spec 字段为准

## 这是同一次发布

2.0 的各项工作（`v1.46` ~ `v1.50`）在**同一天、同一个未发布的工作树**里完成：

| 版本 | 时间 | 提交 | 内容 |
|---|---|---|---|
| v1.46 | 上午 | `2900fa0` / `c9108af` | SPEC-v2 成文、SPEC-v1 纳入版本管理 |
| v1.47 | 14:03 | `b013257` | `JR9001` 弃用警告（双轨第一步） |
| v1.48 | 14:14 | `d793679` | `map.get` → `Option<V>`，删除旧行为 |
| v1.49 | 14:59 | `ba5d666` | 清理双轨脚手架、覆盖率盘点接入验收 |
| v1.50 | 15:12 | `103eaa9` | `T? → T` 不再静默 unwrap（修复 P1） |

**仓库在这些提交之间没有 tag、没有对外发布。** 因此 `v1.47` 的 `JR9001` 警告从未到达用户，

SPEC-v2 的 `JR-V4` 已如实记录这一点，不声称存在用户可见的双轨缓冲期。

## 破坏性变更（请重点阅读）

### 1. `map.get(k)` 返回 `Option<V>`，键缺失不再 panic

```java
// 1.x：键缺失 → panic
int v = m.get("k");

// 2.0：键缺失 → null（Option::None）
Integer? v = m.get("k");
if (v != null) {
    int n = v;
    println(n);
}
```

`getOrNull(k)` 保留为**完全等价的显式别名**（产物相同），已写的代码不必改。

### 2. `T?` 赋给非可空 `T` 必须显式判空

1.x 的隐式 `.unwrap()` 已删除。未判空的写法现在**在编译期阻断**（`JR6007`），
不再等到运行时 panic：

```java
// 1.x：check 通过，运行时可能 panic
int bad = m.get("zzz");

// 2.0：error[JR6007] 阻断构建
int bad = m.get("zzz");   // ❌

// 正确写法
Integer? v = m.get("zzz");
if (v != null) {
    int bad = v;          // ✅ 判空分支内取值
} else {
    println("missing");
}
```

判空分支内的 `.unwrap()` 仍会生成——此时已确认非空，语义安全。

## 其他变化

- **类型检查前移**：名称解析、未知方法、非 bool 条件、类型兼容、二元运算提升、内置方法白名单
  全部在 `jrust check` 阶段报出（v1.41–v1.45 六阶段，SPEC-v2 §2）。
- **三个入口诊断统一**：`check` / `build` / `run` 走同一个检查阶段，同一源码得到同一个诊断码。
- **验收扩为十一步**：新增产物快照（118 项 sha256）与附录 A 覆盖率盘点（58 项），
  两者都进入 CI。
- **String 方法映射**：`length()` → `chars().count()`（按字符而非字节）、`trim` /
  `toUpperCase` 等语义等价换名；`substring` / `charAt` / `split` / `replace` / `indexOf`
  因语义差异不映射，报 `JR6004` 并建议 `raw`。
- **块作用域修复**：内层同名变量不再覆盖外层类型（此前会生成语义错误的产物）。

## 兼容性承诺

除上面两项破坏性变更外，1.x 合法的 `.jrust` 程序在 2.0 下必须仍然合法且行为等价
（`JR-V2`）。如果发现其它差异，请按缺陷报告。
