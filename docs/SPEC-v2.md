# jrust 语言规范 v2

> 编号：JR-SPEC-2.0　状态：草案（Draft）　日期：2026-11-27
> 基础：[SPEC-v1.md](SPEC-v1.md)（JR-SPEC-1.0）继续有效；本文只规定 **2.0 的增量、变更与验收**。
> 两者冲突时以本文为准。状态图例沿用 v1：`✅` 已实现　`🚧` 规划　`❌` 不做　`❓` 待确认。

## 0. 定位

- **1.0**（已收口）：可读、可编译的 Java 风格子集，验收等级 L0–L5 全部 ✅。
- **2.0**（本文）：把「用 Java 风格写任意 Rust」变成**可执行的契约**——先有工程级类型信息与检查阶段，
  再谈语法覆盖。设计背景与六阶段拆解见 cairn 设计文档 §14。
- 形态层约束不变：源码级转译、产物必须是普通 Rust、零外部依赖、确定性（v1 §1.1–§1.2）。

## 1. 版本与兼容契约

- **JR-V1** 规范版本与实现版本分离：`jrust --version` 必须输出 `jrust 0.x.y (spec 2.0)`。
  规范版本记在 `src/main.rs` 的 `SPEC_VERSION`，实现版本取 Cargo 包版本。✅ v1.46
- **JR-V2** 兼容承诺：v1 合法的 `.jrust` 程序在 2.0 下必须仍然合法且行为等价，
  **唯一例外**是 §3 列出的破坏性变更；任何其他行为差异都视为缺陷。
- **JR-V3** 检查阶段与转译共用同一份类型信息：`jrust check` 报出的 error 必须在 `jrust build`
  之前复现，不允许「check 通过、靠 rustc 兜底报错」。**`jrust run` 也走同一检查阶段**，
  三个入口对同一源码必须给出同一个诊断码（P2：不再出现「run 说 null、build 说 JR6007」）。
  ✅（v1.41–v1.45 六阶段；v1.51 run 对齐）
- **JR-V4** 破坏性映射必须经过**双轨期**：在一个 MINOR 版本里保留旧行为、同时提供新写法并发出
  `JR9xxx` 弃用 warning；下个 MAJOR 才删除旧行为。
  **本项目的实际情况（v2.0.0 发布说明）**：v1.46 建立机制、v1.47 发 `JR9001`、v1.48 删除旧行为，
  三者**同日完成、未对外发布、无 tag**，因此双轨期只存在于开发过程中，**用户面对的是一次
  2.0 发布内的破坏性变更，不存在对外缓冲期**。此处如实记录，不声称存在用户可见的双轨窗口。
  ✅（机制 v1.46；警告 v1.47；切换 v1.48；发布说明 v2.0.0）
- **JR-V5** 产物形态稳定性：任何阶段/版本都不得改变既有产物，除非该变更明确列入 §3；
  由 `tests/snapshot.sh --check`（117 项 sha256）守住。✅ v1.40

## 2. 类型检查（规范性）

> 本节把 v1 §13.5 升格为 2.0 的强制契约。v1 §13.5 保留作为历史记录，自 2.0 起以本节为准。
> `check` 与 `build` 都执行；error 阻断产出，warning 不影响退出码（v1 JR-G6）。

### 2.1 名称解析

- **JR-T10** 类型位置的名字必须能解析到：本工程 class / interface / enum、泛型参数、内建类型名。
  - 存在拼写相近的已声明类型（Levenshtein ≤ 2）→ **error `JR6001`**，提示给建议；
  - 纯未知 → **warning `JR6102`**（可能是外部 crate 类型）。
- **JR-T11** `var` 不支持（v1 JR-T7 的检查面）：`var x = 1;` 报 `JR6001`，提示写全类型。
- **JR-T12** 方法调用：接收者类型可解析且（含接口 / `extends` 链）确实无此方法 → **error `JR6004`**，
  有相近名字时给建议。放行边界：外部 crate 类型（`JR4101` warning）、泛型参数、`raw` 块内（v1 JR-X3）。
- **JR-T13** `if` / `while` 条件必须是 `boolean` → 否则 **error `JR6009`**。

### 2.2 类型兼容（`assignable`）

- **JR-T14** 赋值不兼容 → **`JR6007`**；`return` 不兼容 → **`JR6008`**。按序判定：
  1. 完全相同（`Boolean` 与 `bool` 同义）；
  2. `T?` → `T?` / `T` → `T?` 放行；**`T?` → 非可空 `T` 必须在 `if (x != null)` 的判空分支内**，否则报 `JR6007`（2.0 破坏性变更，废止 v1 的隐式 `.unwrap()`，见 v1 JR-T1 修订）；
  3. 数值标量：同级或加宽允许，**窄化报错**；
  4. `char` → 数值允许；
  5. 类 → 接口（`implements` / `extends` 链）、接口 → 父接口允许；
  6. `Named("Box")` 与 `Generic("Box", args)` 同名兼容（目标侧常省略实参）；
  7. 泛型参数、外部 crate 类型放行；
  8. 其余不允许，并给 `提示:` 修法。
- **JR-T15** 集合 / 数组不做元素级检查：检查边界停在 `collectList` 的基座类型推断之内（v1 JR-E18）。

### 2.3 标量提升

- **JR-T9** 赋值 / 实参 / `return` / 构造器实参四个落点，按 Java 语义对窄侧插 `as`。
- **JR-T16** 二元运算：算术与关系运算两侧标量不同时提升窄侧（`n + 1.5` → `n as f64 + 1.5`）；
  **同级不提升**（`int / int` 保持整数除法）；`&&` / `||` 两侧必须 `bool`。

### 2.4 内建类型方法

- **JR-E21** String 方法只做语义等价换名：`length()` → `chars().count()`（按字符而非字节）、
  `isEmpty/equals/toString/startsWith/endsWith/contains/toUpperCase/toLowerCase/trim` 一一对应。
  **不映射**并报 `JR6004` + 建议 `raw`：`substring` / `charAt` / `split` / `replace` / `indexOf`。
- **JR-T17** String / List / Map / Set 的方法白名单必须与 codegen 映射表、`infer_type` 返回类型表一致。

### 2.5 外部类型 = 显式不可知

外部 crate 的类型没有源码可分析，是**显式的不可知状态**，不是「推断失败」：
对它的一切判断（方法、字段、签名）必须降级为放行 + `JR4101` warning，不得静默猜、也不得武断判错。

## 3. 破坏性变更（2.0 唯一一项）

| # | 变更 | 现状 | 双轨计划 |
|---|---|---|---|
| 1 | `map.get(k)` 返回 `Option<V>`（键缺失为 `None`，不再 panic） | ✅ **已切换（v1.48）**：产物 `.get(&k).cloned()`，与 `getOrNull` 完全等价 | 双轨期已结束（v1.47 的 `JR9001` 警告已删除），旧行为 `.cloned().unwrap()` 不再存在 |

- **JR-V6** `getOrNull(k)` 与 2.0 的 `get(k)` **产物完全相同**（都是 `get(&k).cloned()`），保留为显式别名。
- **JR-V7** 切换已完成（v1.48）：文档、实现、解释器三处一致返回 `Option`。不存在「文档写 None、实现仍 panic」。
- 迁移示例：`String v = m.get("k");` → `String? v = m.get("k");`（或显式写 `getOrNull`，两者等价）。
  v1 代码里直接 `println(m.get(k))` 的写法现在会报「不能直接打印可空类型」，需先判空。

## 6. 与 v1 的差异清单

- **新增诊断码**：`JR6001`（未知类型，error）、`JR6102`（未知类型，warning）、`JR6004`（未知方法）、
  `JR6007` / `JR6008`（赋值 / 返回不兼容）、`JR6009`（条件非 bool）、`JR4101`（外部类型不可知，warning）。
- **新增需求号**：`JR-T9`–`JR-T17`（类型层）、`JR-E21`（String 映射）、`JR-V1`–`JR-V7`（版本与兼容）。
- **行为收紧**：v1 中「静默透传给 rustc」的写法（`var`、拼错类型/方法、实参类型、窄化赋值）
  现在在 `check` 阶段报错；错误输出格式继续沿用 v1 JR-G7（`path:line:0: error[码]: 消息`）。
- **不变**：§13.1 的 6 项永久不做；`raw` 块不参与 jrust 诊断；产物形态与命名规则。
